# Phase 3.1 — delegation via scratchpad, not MCP

The swarm plan calls for the manager pane to expose `delegate(target_pane_id,
task, expected_artifacts)` via an MCP server (`--mcp-config` on claude). That
gives a typed, schema-validated tool call surface and the cleanest UX from the
manager agent's perspective.

We're shipping a simpler equivalent first: **delegate via the existing
`.apas-team.jsonl` scratchpad** (Phase 2.2). A manager or Tech Lead pane
appends a JSON line with `tags` containing `delegate-to:<pane_id>` plus a
current task key such as `task:<TODO-NNN...>`; the CLI's scratchpad watcher
recognizes the `delegate-to:` prefix and routes the record's `body` into the
target pane's input queue (the same channel that handles user input).

Why simpler-first:

- **Zero new infrastructure.** No MCP runtime, no schema definitions, no
  separate config file the user has to wire up. The scratchpad watcher and
  per-pane input channels already exist.
- **Visible by default.** Every delegation also appears in the Team modal
  (because it's a scratchpad record), so the human can see what the manager
  routed where without any extra UI.
- **Symmetric with reply convention.** Worker diffs, decisions, and reviews
  carry the same `task:<TODO-NNN...>` tag as the delegation, so the Overview
  Delegation Board can pair both sides by that current task key. Older
  `reply-to:<task_id>` or `task-id:<uuid>` tags can remain as compatibility
  hints for legacy records.

The MCP path stays open as a follow-up if/when the scratchpad approach proves
limiting (e.g. the manager wants strict input schemas, or we want to expose
delegation to non-claude providers that don't read JSONL conventions).
