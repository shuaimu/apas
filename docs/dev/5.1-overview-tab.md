# Phase 5.1 — overview tab design

A pseudo-tab pinned at the front of the TabBar (label "Overview") that
shows the state of the whole team at a glance, without clicking through
each per-pane tab. Same active-tab state we already persist per project,
so flipping back to a regular tab is a no-op.

## Sections (top → bottom)

1. **Header strip** — project name + roll-up counts:
   `N panes · K active · M paused · ⚠ X pending reviews`.
   Clicking the pending-reviews count scrolls/focuses the existing
   Plan Review card stack at the bottom of the page.

2. **Pane grid** (main payload). One card per pane, ~3 across on
   desktop:
   - Tab label + role chip (if set) + provider/model badge
   - Current status pill (same string the per-pane header shows)
   - Mode indicator: ⏵ deadloop running, ⏸ deadloop paused, •
     interactive idle, ● interactive thinking
   - Worktree info if isolated: branch name + diff stats (`+12 -3`)
   - Last activity timestamp
   - Quick action row: Interrupt, Diff, Role, Open-this-tab
   - Click anywhere else → jumps to that tab

3. **Team scratchpad ticker** — last ~20 records from `.apas-team.jsonl`,
   same row shape as the existing Team modal but inline. Filter chips
   along the top: `diff` / `review` / `decision` / `status` / all.

4. **Delegation board** — small table of recent `delegate-to:<pane_id>`
   records, keyed primarily by `task:<TODO-NNN...>` tags and paired with
   replies or worker records carrying the same task tag. Legacy
   `task-id:<uuid>` / `reply-to:<task_id>` tags can be treated as
   fallback correlation for older records. Columns: from-pane → to-pane,
   task tag (short), body preview, status (`awaiting reply` /
   `replied (Δt)` / `untracked`). Loose correlation only; no graph viz
   for v1.

5. **Resource use** — collapsed row of UsageLimitsDisplay per supported
   provider (Claude / Codex / DeepSeek) so usage is visible
   without clicking individual tabs.

6. **Live activity sparkline** *(optional, v2)* — per-pane last-hour
   sparkline of StreamMessage emissions; spot wedged deadloops.

## Implementation notes

- Zero new wire types. Every datum already flows through the store
  (`paneConfigs`, `paneStatuses`, `paneMessages`, `teamRecords`,
  `planReviewPending`, `usageLimits`, `paneDiffs`).
- New layout component `OverviewView.tsx` + tiny additions to TabBar
  for the pinned pseudo-tab + an `activeTabId` sentinel value (0 is
  free; use 0 to mean "overview").
- Section components live alongside in `components/overview/`.

## Sub-split

- **5.1a** — scaffold: pinned "Overview" tab in TabBar, sentinel
  activeTabId, empty OverviewView shell. Make the toggle work so
  switching back to a normal tab is seamless.
- **5.1b** — pane grid section.
- **5.1c** — scratchpad ticker section with filter chips.
- **5.1d** — delegation board section.
- **5.1e** — resource-use rollup section.
- **5.1f** *(optional)* — live activity sparkline.

## Tradeoff

The overview duplicates info available via clicking each pane, so
the value is purely "spot trouble without N clicks." Payoff scales
with team size: at 2–3 tabs it's mild polish; at 6+ (closer to a
swarm) it becomes the primary view. The delegation board and
sparkline are the bits that don't exist anywhere else today.
