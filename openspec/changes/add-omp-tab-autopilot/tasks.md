Group 1 comes first on purpose: the design rests on reading OMP's source, and
nothing in it was run. Groups 2 to 7 are in build order (contract, extension,
CLI, server, web). Deployment order is different: shared contract and server,
then web, then CLI and daemon, as in `design.md`. Nothing here deploys anything
or restarts a running agent.

## 3. Run the loop in the OMP extension

- [ ] 3.1 Read the two request files and the controller heartbeat from a managed timer once a second, started only for the main agent of a TUI session. Read them with a 64 KiB bound, not the 8,192-byte bound of the activity report. Never delete the pause-or-stop file: record each applied request id in the acknowledgement file and treat an acknowledged request as no longer pending. Apply a pause or stop that passes the trust checks whatever its format version and unknown fields. Take a start or resume by renaming its file before applying it, and refuse one issued more than two seconds ago or in the future. Apply pending requests in the order they were issued; remember applied request ids; acknowledge as accepted a request that changes nothing; put the launch, pid and process-start fields and a format version on every file.
- [ ] 3.2 Implement the actions: start, validating the bounds again, refusing one that leaves a limit out instead of saying "none", rejecting unknown fields, and refusing a second start; pause; resume, only for the named paused autopilot and never after a deadline that has passed; stop; and stop now, which flags its own abort, aborts the run of an outstanding submission if one starts, and reports "Stopped" when that run has ended or, when OMP records the prompt without a run, once the message is recorded and the tab is idle.
- [ ] 3.3 Implement the loop on the extension's existing settled state: the settle conditions of decision 3, the poll that reads a background wait as over, the due time for both timings, the outstanding-submission marker (cleared when the extension sees its own message recorded, when the call rejects, and when the session is switched or reloaded), the single synchronous step before a submission, submission with agent attribution and `aside` delivery, a rejection journaled as "not submitted" only while the submission is outstanding, clearing a dropped prompt from the input line when it holds the prompt as OMP's editor stores it, and continuing after a turn the person started.
- [ ] 3.4 Implement the limits, each of which may be "none": the iteration counter, which only reports progress when there is no iteration limit; with a time limit, the deadline on its own timer, armed for at most a day at a time, armed again at `session_start` for a restored autopilot, ending autopilot in every condition and when the next iteration would be due after it; the no-tool-call ending, which never applies to a failed or interrupted iteration; the one-minute wait after a failure and the pause after three consecutive failures, counted again from a resume; and the order when several rules apply at the end of one turn (a requested stop, the time limit, the iteration limit, then the pauses, with the no-tool-call ending only when no other rule applies).
- [ ] 3.5 Classify how each turn ended from the last `turn_end` before the terminal `agent_end`, and a dropped submission by whether it carries a refusal reason. Pause autopilot for each interrupt signal of decision 4, but not for the extension's own aborts: a turn aborted with the user-interrupt marker; a wait for background work that ended without a wake, five seconds after the poll first reads it as over unless a run has started; a cancelled retry; a cancelled automatic compaction; and a submission dropped without a refusal reason.
- [ ] 3.6 Journal the autopilot in the OMP session with the prompt in the start entry only. Read the latest entry of the active branch, ignoring other sessions' entries, at `session_start` and after every `session_switch`, `session_branch` and `session_tree`: restore at `session_start` as paused, or as ended when it has a deadline that has passed; end an autopilot that a position reached inside the process still shows as not ended; and report the last ended autopilot. End autopilot when the tab leaves its conversation, writing the end entry where it is read back, but never from `session_before_branch` with the reason `btw`, and not for a reload, which keeps the autopilot and resets the settled state and the outstanding-submission marker. Keep the ended autopilot in the report until another starts or the agent restarts.
- [ ] 3.7 Note on the extension's own clock when the heartbeat's writer id or counter last changed. Hold, whether or not an iteration is due and whether or not a turn is in progress, while neither has changed for 60 s, while the heartbeat reports the server unreachable for more than 600 s, or while it reports that the server cannot control autopilot. Report the condition holding while a hold lasts and no turn is in progress. Continue when the hold ends within four hours, and pause with "Paused: APAS could not control this tab for more than four hours" as soon as a hold has lasted four hours.
- [ ] 3.8 Write the state report on every change and at least every 30 s, with its version and counter, the autopilot's start time, the last ended autopilot with its prompt, timing and limits and whether a turn that started after it ended has run, and OMP-supplied text cut to 500 characters, all within 64 KiB. Show the condition in the terminal's own status line.
- [ ] 3.9 Report OMP's goal and loop modes, active and paused, taking a goal's tokens used and real status from `goal_updated`. Refuse a start or resume, and pause autopilot, while goal, loop or plan mode is in any state other than off or autoresearch is on (its `init_experiment` tool is active), checking again before each submission, with the refusal and pause text the spec gives for each.
- [ ] 3.10 Keep publishing Working while the next iteration is scheduled within ten seconds, and across a built-in mode's gap, falling back to Idle 15 s after a run was due and did not start.
- [ ] 3.11 Check OMP's version against the minimum and detect every call autopilot uses, reporting "unsupported" when one is missing. Isolate autopilot so that a fault in it cannot stop activity reporting or the question bridge.
- [ ] 3.12 Cover 3.1 to 3.11 in `omp_activity.test.mjs`, including an autopilot with no limit, the age limit and a start that the CLI withdrew first. Append `node --experimental-vm-modules --test ../../crates/client-cli/src/omp_activity.test.mjs` to the protocol package's test script after `vitest run`: the file uses `node:test` and `vm.SourceTextModule`, which vitest does not collect. The gate is the local run in 8.1; the repository's workflow runs on pull requests and on pushes to `main` only.

## 4. Relay it through the CLI

- [ ] 4.1 Have `install()` clear the autopilot files at each provider launch, as it already clears the activity and question files, an unapplied pause or stop included (it is not carried over; the autopilot comes back paused), and record the autopilot feature marker in `omp-launch.json`.
- [ ] 4.2 Implement the exchange under its own lock, waited for at most one second, with the issue time stamped after the lock is taken and every file within 64 KiB. For a pause or stop: write it unless an equal or stronger one is pending, wait two seconds for the acknowledgement, answer "uncertain" on timeout with no resend, leave the request in place, build it from the launch record alone, and remove an acknowledged request the next time the lock is held. For a start or resume: wait two seconds, then remove the file; if the removal succeeds answer refused with "The tab did not take the request in time. Nothing was started."; if the file is gone wait one more second for the acknowledgement and answer it, or "uncertain" when none arrives.
- [ ] 4.3 Read the state report with the existing trust checks and a 64 KiB bound, send the time it was last seen refreshed with it, treat one not refreshed for 90 s as not reported (except for the state of 4.8), derive the tab's `support` value from the launch marker and the report, and send `PaneAutopilotState` on every change and for every OMP tab after each registration. Accept unknown fields in the report.
- [ ] 4.4 Add explicit connection state to the project runtime: connected, set when a registration completes and cleared at the top of each reconnect attempt; the time of the last inbound frame; and whether the server echoed `omp_tab_autopilot_v1`. Write the heartbeat for each OMP tab every three seconds from a thread of its own that never sends on the outbound queue, with a writer id chosen at random when the CLI process starts, a counter, and durations from the monotonic clock.
- [ ] 4.5 Handle `ControlPaneAutopilot` in the project runtime, validating a start again, and answer with `PaneAutopilotReceipt`. Refuse it in modes that cannot serve it.
- [ ] 4.6 Make the transcript reader publish an iteration as the reserved tool-use block and never as a user turn, by the pairing rule of decision 3, with the prompt on the first marker of each autopilot and on the first after each resume, and with `limit` left out when the autopilot has no iteration limit. The marker is not carried in the turn's question field, which the question replay owns. Test it with a captured OMP session file that includes a dropped submission and a person's message sent during autopilot.
- [ ] 4.7 While the live OMP report says Working, send a turn's completing message with `terminal_turn_complete: false` and skip the explicit clear.
- [ ] 4.8 When the agent process of a tab whose last relayed autopilot state was on or paused exits without the CLI having asked for it, report "Paused: the agent process exited" for that tab: built from the state last relayed for that launch, not from the tab's files; marked as reported by the CLI; in place of "not reported" and exempt from the 90-second rule; sent again after each registration; and dropped when the agent is launched again. Refuse an autopilot request for a tab whose agent process has exited with "This tab's agent is not running. Reboot it first; its autopilot comes back paused."
- [ ] 4.9 Advertise `omp_tab_autopilot_v1`.
- [ ] 4.10 Test the exchange with a responder thread as the question bridge's tests do, plus the trust rejections, a stale report, the reconnect re-report, the pause reported after an agent exit (it replaces "not reported", is not reported for an exit the CLI asked for, and makes the CLI refuse requests for that tab), both outcomes of removing a start at the end of the wait, a heartbeat that keeps being written while the outbound queue is full, and that with a live report of Working the completing turn is sent with `terminal_turn_complete` false and no status-none frame follows it.

## 5. Authorize, route and remember it on the server
