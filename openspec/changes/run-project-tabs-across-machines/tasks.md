Phases are ordered so each one is independently shippable: Phase 1–3 make a
second instance on a shared home work (started from the Machines page), Phase 4
adds choosing a machine from the new-tab menu, Phase 5 joins separate
checkouts, Phase 6 clones onto a machine, Phase 7 covers native mobile.

Every task names its owner in brackets. A task split between owners names the
owner of each part and is done when every part is. The server track works only
in `crates/server` and runs S1, S2a, S2b, S3 in that order; the CLI track works
only in `crates/client-cli` and runs C1, C2a, C2b, C3; the web track works only
in `packages/web` and runs W1, then W2; M1 is native mobile; H1 is the
smoke-test harness, kept outside the repository. [Later] marks work after
integration: the integration review, the real smoke tests, `AGENTS.md` and
deployment. Keeping these documents in line with the committed contract has no
task of its own.
